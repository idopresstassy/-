# 독자마당

홈 상단 `독자마당` 또는 `/community`에서 이용합니다. 도서 뷰어 설정의 `이 책 문의하기`는 낭독을 일시정지한 뒤 관련 도서가 선택된 작성 화면으로 이동합니다. 로그인 전이라면 로그인 후 해당 작성 화면으로 돌아갑니다.

## 운영

- 비회원: 공개된 공지사항·책 이야기·문의/건의 열람.
- 회원: 글/댓글 작성, 본인 글/댓글 수정·삭제, 비공개 문의, `내가 쓴 글`, 새 답변 확인.
- 관리자: `/admin?tab=community`의 `독자마당 관리`에서 비공개 문의를 포함한 글 검색·답변·숨김/복원. 공지사항 작성 및 상단 고정.
- 이메일 대신 별도 닉네임을 표시합니다. 관리자 작성은 `책방지기`와 관리자 표시를 사용합니다.
- 글의 공개 범위는 작성 후 변경되지 않습니다. 비공개 문의는 제목, 본문, 댓글 모두 작성자/관리자에게만 표시됩니다.
- 숨긴 글은 작성자/관리자만 열람 가능하며 새 댓글/수정은 막습니다. 숨긴 댓글은 관리자에게만 표시합니다.
- 글 삭제는 본인만 가능하며 제목·본문·해당 댓글 내용도 지웁니다. 댓글 삭제는 본인만 가능합니다. 삭제는 복원하지 않습니다. 운영용 삭제 표시/시각은 계정 탈퇴 시 함께 삭제됩니다.
- 답변 알림은 게시판의 배지입니다. 본인 글에 다른 사람이 남긴 공개 중 댓글을 기준으로 계산하며, 최신 댓글을 열어 확인하면 읽음 처리됩니다.
- 일반 회원 도배 제한: 글 10분당 5개/하루 50개, 댓글 분당 10개/하루 200개. 삭제한 글도 빈도에 포함합니다.

## 데이터와 접근

`20261119120242_readers_community.sql`을 먼저 적용하고 웹 서버를 배포합니다. 추가 환경 변수는 없습니다. 기존 서버 전용 Supabase service role 연결을 사용합니다.

`community_members`, `community_posts`, `community_comments`, `community_reads`, `community_post_summaries`는 Data API의 anon/authenticated 직접 접근을 허용하지 않습니다. RLS를 활성화하고 service_role만 접근합니다. 읽기는 서버에서 신뢰한 세션을 기준으로 필터링하며 검색/건수/페이지 처리 전에 적용합니다. 쓰기는 서비스 전용 `community_write` 함수에서 현재 DB 역할, 소유권, 부모 문의 접근, 수정 버전, 도배 제한을 다시 검사합니다.

`viewerKey`는 브라우저 캐시를 계정별로 구분하는 용도이며 권한 부여에는 사용하지 않습니다. 로그아웃/계정 변경 시 커뮤니티 캐시를 제거합니다. API 응답은 `private, no-store`이고 서비스 워커는 API를 캐시하지 않습니다.

본문은 일반 텍스트로 출력합니다. 계정 이메일과 작성자 UUID는 게시판 응답에 포함하지 않습니다. 새 기능의 개인정보 처리 항목은 `/privacy`에 추가했습니다.

## 검증

- `pnpm check`, `pnpm test`, `pnpm build`
- `supabase/tests/community_access.sql`: 실제 PostgreSQL에서 생성한 가상 회원/게시물만 사용하고 전체 트랜잭션을 ROLLBACK합니다. 비공개 문의 접근, 권한 위조, 관리자 전용 기능, 읽음 표시 경쟁, 수정 충돌, 숨김/복원, 빈도 제한, 삭제 시 내용 제거, anon/authenticated 직접 접근 거부를 검사합니다.
- 화면 확인: 회원 글쓰기 → 비공개 문의 → 관리자 답변 → 작성자의 새 답변 확인 → 숨김/해제 → 제목 검색 → 로그아웃. 390px 휴대전화 너비의 목록/작성 화면도 확인합니다.

기존 도서/회원 데이터나 낭독 캐시를 변경하지 않는 추가 기능입니다. 웹 배포를 되돌려도 새 게시판 데이터는 남겨 복구할 수 있습니다.
