# 창작 사용성 개선 배포 메모

2026-11-09. 기준 main: af5564dd8b1949293a77bff9a02a4538689b6e8e.
PR #1 대신 현재 creative_submissions 기반 구현을 확장한다.

## 변경
- 공개 작품은 기존 홈 창작 탭에서 읽고, /creative에서 작성·관리한다. 직접 창작 탭으로 돌아가는 링크 추가.
- 기기별·회원별 수동 임시 저장/불러오기, 미리보기, 수정 요청 원고 재신청. 임시 저장은 서버 백업이 아니며 다른 기기에는 전달되지 않는다.
- 관리자 수정 요청 사유 필수. 게시 중단/복구와 처리 이력, 원고·회원·독서 기록 보존.
- 공개 목록에서 본문 제외. 본문은 상세에서 요청. 서버와 직접 DB API 모두 비공개 작품을 읽지 못하게 보호.
- profiles.role의 회원 직접 수정을 차단하고 이름 수정은 유지한다.
- 기존 장르 값은 그대로 사용한다. 시·수필·동화는 현재 '기타'로 제출할 수 있다.

## 적용 순서
1. 운영 books/profiles/auth/creative_submissions/독서 데이터와 파일 저장소의 복원 가능한 백업 확인. 현재 수량과 ID·본문/파일 참조를 기록. 과거 보고서의 241/252권을 현재 기준으로 사용하지 않는다.
2. 테스트 DB에서 추가 마이그레이션 `20261109091458_creative_visibility_and_resubmission.sql` 검증 후 운영 적용. 기존 마이그레이션 재실행/초기화 금지.
3. 실제 운영의 추가 profiles UPDATE 열 권한과 책 조회 정책도 검사한다. 허용할 회원 프로필 편집 항목이 이름 이외에도 있다면 역할 변경 권한은 제외하고 검토한다.
4. 이 커밋의 check/test/build 통과 후 Render에 배포. 새 코드의 목록 조회에는 is_public 열이 필요하므로 DB를 먼저 적용한다. 이전 앱은 service_role로 숨김을 우회하므로 마이그레이션만 적용한 상태에서 게시 중단을 사용하지 않는다.
5. 실제 계정 A/B/관리자로 로그인·작성·재신청·승인·중단·복구·회원 간 격리를 검증한다. 기존 도서 읽기·검색·회원 로그인·책장·업로드도 확인한다.
6. 구형 앱으로 롤백하면 비공개 필터가 없어 숨긴 작품이 다시 노출될 수 있다. 숨긴 작품이 있는 경우 접근을 제한한 뒤 수정 배포하며, 테이블/원고를 삭제하거나 과거 DB로 덮어쓰지 않는다.

## 검증
- TypeScript check, 전체 Vitest 52개, 프로덕션 클라이언트/서버 빌드 성공.
- 별도 로컬 PostgreSQL 호환 PGlite에서 추가 SQL 실행: 기본 도서 공개 유지, 숨김/복구, 직접 읽기 RLS 차단, 일반 회원 RPC 실행 불가, 관리자 확인, 처리 로그, 기존 본문·읽기 기록 보존, 회원 role 변경 차단 확인.
- 운영 DB·실계정 통합 검증 및 Render 배포는 아직 수행하지 않았다.
- 빌드에는 기존 분석 환경변수 누락 및 번들 크기 경고가 남는다.

## 제한
- 이미 다운로드하거나 오프라인 저장한 본문은 원격으로 회수할 수 없다.
- 기존 신규 접수의 최대 5편 검사는 동시 요청에 대한 DB 수준 엄격한 제한이 아니다. 재신청에도 같은 한도 검사를 적용한다.
- 공개 후 원문 개정·서버에 초안 저장·다회차 연재·파일 첨부는 이번 범위에 포함하지 않는다.
